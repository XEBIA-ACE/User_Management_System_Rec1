- [ ] T001 FR-001 (S1-AC1): The discovery activity SHALL include inspection of the user management service build descriptors and runtime configuration files and SHALL record in the discovery document the Java runtime version used to compile and run the service; where differences between development and production Java versions are known, those differences SHALL be explicitly documented.
- [ ] T002 FR-002 (S1-AC2): The discovery activity SHALL review build-related files and any CI/build instructions in the repository and SHALL document in the discovery document: (a) the primary build tool used for the service (e.g., Maven, Gradle, or custom scripts), (b) the location(s) in the repository of the primary build descriptor(s) or scripts, and (c) a description of how dependencies are managed (e.g., via build tool configuration, external scripts, or other mechanisms); if aspects of dependency management cannot be determined, this ambiguity SHALL be explicitly noted as an unresolved unknown.
- [ ] T003 FR-003 (S1-AC3): The discovery activity SHALL analyze dependency descriptors and source code to identify the primary application/web framework in use; if no standard framework is detected, the discovery document SHALL state explicitly that no standard framework is used and SHALL describe, based on observable code, how HTTP or other external interfaces are provided; if multiple candidate frameworks or interface mechanisms exist and a single primary one cannot be determined, this uncertainty SHALL be recorded as such rather than assumed away.
- [ ] T004 FR-004 (S1-AC4): The discovery activity SHALL review any available deployment instructions, operations contacts, and current deployment artifacts to determine and document in the discovery document: (a) the packaging format of the service (e.g., JAR, WAR, or other artifact) and (b) the hosting/deployment model (e.g., app server, standalone JVM, container, or other), including an explicit statement of whether the service is currently containerized; where deployment details cannot be fully established from the available information, these gaps SHALL be captured as unresolved unknowns.
- [ ] T005 FR-005 (S1-AC5): Upon completion of the discovery work, a concise discovery document SHALL exist in an agreed and reviewable location and SHALL summarize at minimum: (a) Java runtime version(s) in use (including any known environment differences), (b) the primary build tool and dependency management approach, (c) the primary framework or interface mechanism, (d) the packaging format and hosting/deployment model, and (e) the current containerization status, along with any remaining unknowns; subsequent modernization stories SHALL reference this discovery document as their baseline source for these facts.
